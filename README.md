# 뒤바뀐 도서관 · 책을 부탁해!

첨부 픽셀아트를 사용한 모바일 책 받기 게임입니다. 기본 플레이 30초 뒤 마지막 책이 카트/바닥에 도착하면 2초의 추가 정리 시간을 제공합니다. HTML/CSS/JavaScript + Canvas이며 서버, 로그인, 외부 라이브러리나 인터넷 연결이 필요 없습니다.

## 실행

ZIP을 **모두 압축 해제**하고 `index.html`을 Chrome, Edge, Safari 등 브라우저에서 엽니다. `assets` 폴더와 JS/CSS 파일을 함께 유지하세요. ZIP 내부에서 HTML만 열면 그림이 누락될 수 있습니다.

모바일 행사 배포는 이 폴더 전체를 정적 웹 호스팅에 올린 뒤 URL을 QR 코드로 공유하면 됩니다. 휴대전화 파일 관리자에 따라 로컬 HTML 실행이 제한되면 정적 호스팅을 사용하세요. 현재 GitHub Pages 주소는 https://gamemakercho.github.io/library-game1/ 입니다. 변경 후 GitHub Desktop에서 Commit to main → Push origin을 실행하면 업데이트됩니다.

개발용 미리보기(선택): 이 폴더에서 `python -m http.server 8765` 실행 후 `http://localhost:8765` 방문.

## 조작과 규칙

- 숫자 버튼 또는 서가 열을 터치하면 즉시 이동합니다. PC에서는 1–4 키도 지원합니다.
- 카트에는 5권까지 쌓입니다. 받은 책 자체는 점수가 아닙니다.
- 책 꽂기 버튼 또는 스페이스: 4번 위치로 이동하고 한 권당 0.2초씩 정리합니다. 1권은 0.2초, 3권은 0.6초, 5권은 1초입니다. 정리 중에는 이동과 받기가 잠기며, 낙하와 시간은 계속 진행합니다.
- 각 권의 0.2초 모션이 끝날 때 카트에서 한 권을 빼고 점수를 1 올립니다. 목표 15권을 넘겨도 30초 동안 계속 플레이합니다. HUD는 30점처럼 꽂은 권수를 점수로 표시하며 목표 분모는 표시하지 않습니다. 29초부터 새 책 생성 모션을 멈추며, 이미 등장한 책의 낙하는 계속됩니다. 마지막 책의 카트/바닥 판정 후 2초가 지나면 종료합니다(기본 30초는 최소 진행 시간). 그동안 이동과 책 꽂기, 점수 반영이 가능합니다. 추가 시간에는 HUD에 마무리/정리 시간을 표시합니다. 최종 종료 시 15권 이상이면 성공, 미만이면 실패입니다. 생성된 모든 책을 빠짐없이 받아 모두 꽂은 경우에는 ‘완벽하게 정리완료!’와 첨부 특별 이미지를 표시합니다. 카트에 남은 책이나 놓친 책이 있으면 일반 결과만 표시합니다. 종료 전에 완료한 책만 점수로 인정하며 제한 시간과 정확히 동시에 완료되는 책은 제외합니다.
- 탭을 숨기거나 Ⅱ/Escape를 누르면 일시정지합니다. 돌아온 뒤 ‘계속하기’를 눌러 재개하세요. 정지 중 입력은 무시합니다.
- 실패/성공 뒤 ‘다시 도전’으로 모든 상태를 초기화합니다.

## 난이도 변경

`config.js`의 `CONFIG`를 수정하세요. 시간 단위는 밀리초입니다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| duration | 30000 | 기본 플레이 시간; 마지막 낙하에 따라 실제 종료는 늦춰짐 |
| spawnUntil | 29000 | 새 책 생성 모션을 시작할 수 있는 마지막 시점(이 값 미만) |
| cleanupGrace | 2000 | 마지막 책 카트/바닥 판정 후 추가 정리 시간 |
| target | 15 | 목표 정리 권수 |
| capacity | 5 | 카트 적재 한도 |
| shelvePerBook | 200 | 한 권을 꽂는 모션 길이; 전체 입력 잠금은 이 값 × 권수 |
| fallStart / fallEnd | 650 / 300 | 시작/종료 시 한 칸 낙하 간격 |
| spawnStart / spawnEnd | 1200 / 700 | 시작/종료 시 책 생성 모션 간격 |
| dropDuration | 600 | 사서 모션 길이 |
| floorLifetime / floorLimit | 2200 / 6 | 바닥 책 유지 시간/최대 개수 |

낙하 및 생성 간격은 경과 시간 비율로 선형 감소합니다. 각 책의 낙하 간격은 생성 모션 시작 시 고정됩니다. 사서 모션 600ms 종료 후 실제 낙하 책으로 교체해 중복을 방지합니다. 기본 설정은 사서 프레임당 120ms입니다. 고양이는 5프레임 전체를 한 권당 200ms(프레임당 40ms)로 빠르게 재생하고, 권수만큼 반복합니다. 생성 간격은 사서 모션 길이 이상을 권장합니다.

`duration`을 바꾸면 `spawnUntil`도 함께 조정하세요(기본은 duration보다 1000ms 작음).

`layout`의 좌표는 원본 배경 1103×1426 기준입니다. 실제 서가 칸 중심 `[125,326,528,735]`를 낙하, 카트, 버튼이 공유합니다. 오른쪽 행동 버튼은 다섯 번째 열이 아닙니다. 배경을 바꾸면 이 좌표도 조정하세요.

## 후속 퍼즐 연결

`CONFIG.nextPuzzleUrl = './next-puzzle.html'`로 지정하면 성공 화면 버튼이 ‘다음 단서로’ 바뀝니다. 자동 이동은 하지 않습니다.

또는 `game.js` 이전에 별도 스크립트를 추가해 콜백/이벤트를 연결하세요. 추가 정리 시간까지 종료한 후 성공 결과가 확정될 때 각각 한 번만 호출됩니다. 목표를 넘긴 순간에는 호출하지 않습니다.

```js
window.onGameComplete = ({ score, elapsedMs }) => {
  console.log('성공', score, elapsedMs);
};
window.addEventListener('bookcatch:complete', event => {
  console.log(event.detail);
});
```

## 에셋과 구현

플레이에 필요한 이미지는 `assets`의 WebP로 정리했습니다. 원본 PNG는 별도 `bookcatch-original-assets.zip` 백업에 보관하며 배포 폴더에 넣지 않습니다. 모션 JSON은 그대로 포함합니다. `empty-cart`, `pushing-cat`, `stack-*`는 원본 카트 그림에서 픽셀을 분리한 파일입니다. 기존 3권을 제거한 빈 카트 위에 실제 적재량만 표시합니다. `*-trim`은 투명 여백을 줄인 원본 그림입니다. `librarian-idle.webp`는 떨어뜨리기 모션의 마지막 프레임에서 떨어진 책만 제거한 그림으로, 모션과 같은 크기 및 접촉 기준점으로 표시됩니다. 새 그림체를 생성하지 않았습니다.

`motion-data.js`는 원본 JSON을 JS로 옮긴 데이터입니다. 로컬 `file://` 실행에서 JSON fetch 제한을 피합니다. 모션은 JSON의 개별 rect, anchor_in_rect, offset_in_canvas, frame_canvas, duration_ms를 사용합니다. 단순 5등분하지 않습니다. 책 꽂기 중에는 미는 고양이를 숨깁니다. 배경 서가나 화분을 추가하지 않습니다.

`engine.js`는 화면과 분리된 시간 기반 판정, `game.js`는 입력·렌더링·모션·일시정지를 담당합니다. Canvas는 imageSmoothingEnabled=false, CSS는 image-rendering:pixelated를 사용합니다.

## 검증

자동 판정 테스트 20개 통과: 네 칸 이동/고정 박자, 즉시 이동/0–5 적재/초과 낙하, 1–5권의 비례 정리 시간, 권별 점수/적재 감소, 정리 잠금/낙하 지속/중복 방지, 시간 경계/부분 완료 점수, 30/15와 30초까지 진행, 재시작, 프레임 속도 독립성, 점진 가속, 바닥 책 제한/소멸, 29초 생성 중지, 마지막 낙하 및 2초 정리, 생성 중지 시각 경계, 추가 시간의 프레임 속도 독립성, 전체 생성 책의 완벽 정리, 놓친 책/미정리 책의 퍼펙트 제외, 결과 확정 전/재시작 시 퍼펙트 해제, 빈 게임의 퍼펙트 제외.

실제 브라우저에서 에셋 로드, 플레이 화면, HUD 점수와 적재량 변화 및 360×740 배치를 확인했습니다. 짧은 뷰포트 상단 잘림을 수정했습니다. 실제 iOS/Android 기기에서의 터치 및 백그라운드 전환은 별도 현장 점검을 권장합니다. 자동 테스트는 `node tests/engine.test.cjs`로 다시 실행할 수 있습니다.

이미지 로드 순서 회귀 검증: `node tests/loading.test.cjs`. 배경이 먼저 로드되어도 모든 이미지가 준비될 때까지 렌더링을 기다려 애니메이션 루프가 멈추지 않는지 확인합니다.

완벽 결과 이미지: `assets/perfect-clear.webp`. 성공 콜백/이벤트의 기존 score, elapsedMs에 perfect(완벽 여부), totalBooks(생성 권수), missed(놓친 권수)가 추가됩니다. `BookGame.isPerfect`로 판정을 확인할 수 있습니다.

## 이미지 압축과 데이터 사용량

배경을 제외한 이미지 12개는 무손실 WebP이며, 원본 PNG를 디코딩한 RGBA 픽셀과 한 픽셀도 달라지지 않는 것을 확인했습니다. 모든 이미지의 원래 크기와 모션 좌표를 유지합니다. 배경만 WebP quality=85, method=6으로 압축했고 1103×1426 해상도를 유지했습니다.

- 이미지 합계: 5.70MB → 3.07MB.
- 첫 접속 파일 합계(이미지+HTML/CSS/JS): 약 5.73MB → 3.09MB, 약 46% 감소.
- 배경: 1.44MB → 0.077MB, 약 95% 감소.
- 사용하지 않는 PNG 원본을 백업으로 분리해 배포 폴더도 약 10.37MB → 3.12MB로 감소.

위 숫자는 1MB=1,000,000bytes 기준의 파일 크기 합계입니다. 실제 전송량에는 HTTP 헤더 등이 더해지고 HTML/CSS/JS 전송 압축에 따라 조금 줄어들 수 있습니다. 최초 접속은 약 3.1MB를 예상하면 됩니다. 플레이와 다시 도전은 이미 로드한 그림을 재사용하며 점수/타이머를 서버로 보내지 않습니다. 다음 방문은 브라우저 캐시 상태에 따라 데이터 사용량이 더 줄어듭니다. 새 압축 버전의 첫 접속에서는 WebP를 새로 내려받습니다.
